# Track Session Minder

A track day (HPDE) schedule app for iPhone and Android. Drivers see which run
group is on track now, who is up next, and the full day's schedule. An admin
can shift the schedule when the day runs late.

Built with [Expo](https://expo.dev) (React Native) and Expo Router.

## What's here

- `src/app/` – the screens: **Events**, **Now**, **Schedule**, **My Day** and **Admin**. The Admin tab only
  appears for signed-in admins; to sign in, open `/admin` (on the web: https://kpctoy-png.github.io/Track-Session-Minder-App/admin)
- `src/data/sampleEvents.ts` – the Roebling and Barber schedules, copied from the Just Track It PDFs
- `src/lib/schedule.ts` – time math: what's on track now, what's next, shifting the day when running late
- `src/lib/ScheduleStore.tsx` – loads the events and listens for live changes
- `supabase/` – the online database setup (`setup.sql` is generated by `npx tsx scripts/generate-setup-sql.ts`)

## Online database

Schedules live in [Supabase](https://supabase.com). Anyone can read them,
and every change reaches open apps within seconds. Each event belongs to a
club: a club's admins can change only that club's events, and platform
admins (Redline Techniques) can change everything. `supabase/admin-snippets.sql`
has copy-and-paste SQL for adding clubs and admins. Club logos live in
`assets/clubs/` (or a club's `logo_url`).

1. Run `supabase/setup.sql` in the Supabase SQL Editor (again after updates that change it; it only adds what's missing).
   The first run makes the accounts that already exist platform admins.
2. Add club organizers in the app: platform admins see **Manage organizers** at the
   bottom of the Admin tab (email + club, stored in `club_organizers`). Organizers
   sign in at `/admin` with an emailed code. Accounts made under Authentication → Users
   with a password still work too. Being signed in gives no editing rights by itself:
   only people listed in `platform_admins`, `club_admins` or `club_organizers` can edit.
3. Put the project URL and publishable key in `.env`:
   `EXPO_PUBLIC_SUPABASE_URL=...` and `EXPO_PUBLIC_SUPABASE_KEY=...`

Without `.env`, the app runs on the built-in sample events in practice mode.

### Coaching sessions and driver sign-in

Admins book a paid coaching session for one student by email (Admin tab →
Coaching). The student signs in on the My Day tab with a one-time code emailed to
them, then sees the session on Me, on Now (with a countdown) and on Schedule.
If the coach's email is entered, the coach sees it too after signing in with that email.
Only that student, the coach and the club's admins can see it. Check rides are booked
the same way (pick "Check ride" in the form). Neither the student nor the
instructor can be in two overlapping bookings on the same day, whether coaching
or check ride (instructors are matched by email, or by name when no email was
entered). A session is linked to a
schedule item, so "running late" shifts move it too.

Signed-in drivers can also ask for coaching from My Day (Request coaching). The card shows
the club's price (`COACHING_OFFER` in `src/lib/coaching.ts`, `COACHING_PRICE` in `push-schedule`), paid at
the event's registration since ClubReg takes no payments once the event starts, and that it's
subject to availability. Once booked, drivers who hadn't paid in ClubReg get a "pay at registration" email. Requests (`coaching_requests`) alert and email the club's organizers
through `push-schedule` (`coaching-request` action, from a trigger) and show at the top of
Admin → Coaching. **Book** fills in the form and marks the request booked once saved;
**Decline** (asks first) tells the driver by email and alert that coaching is full.

Driver sign-in needs three settings in Supabase:

1. Authentication → Sign In / Providers: turn on **Allow new users to sign up**.
2. Authentication → Emails → Templates: in **Magic Link** and **Confirm signup**,
   add the code to the message, for example `<p>Your code: {{ .Token }}</p>`.
3. Authentication → Emails → SMTP Settings: set up a custom email sender
   (for example Resend or SendGrid). Supabase's built-in sender only emails
   the project's team members and only a few emails an hour.

### Coaching emails

When a coaching session is booked, changed or removed, the student and the
coach (if their email was entered) each get their own email, telling them to
sign in with their own address. It is sent by the Supabase
Edge Function in `supabase/functions/notify-coaching`, using the same Google
account as the sign-in emails. One-time setup in the Supabase dashboard:

1. Run `supabase/setup.sql` again. It adds the coach email column and the
   trigger that calls the function.
2. Edge Functions → Deploy a new function → Via Editor. Name it
   `notify-coaching`, replace the sample code with
   `supabase/functions/notify-coaching/index.ts`, and click Deploy.
3. Edge Functions → Secrets: add `SMTP_USER` (the Google address) and
   `SMTP_PASS` (its app password).

No dashboard webhook is needed (creating one as well would send every email twice).

### First session of the day

Some clubs run each run group's first session of the day as warm-up laps. The
Schedule tab and Now cards show a yellow note on it, set per club in
`FIRST_SESSION_RULES` (`src/lib/schedule.ts`). Just Track It: 2 laps, no
passing, yellow flag.

### Announcements

Organizers can put an urgent message (lightning, red flag) in red at the top of
every driver tab, from Admin → Announcement to drivers (one-tap icons such as ⚡
Lightning or 🚑 Medical go in front of the message). It also goes to phones
with alerts on for that event. Platform admins can send one to every driver.
Clearing it offers to make up the time the track was held (push later or
shorten sessions), which the organizer reviews before it is sent. Needs the
`announcements` table from `supabase/schema.sql`.

Organizers can also upload the event's participant list (ClubReg's export, a CSV or an
Excel sheet; a header row is optional) under Admin → Registered drivers. Announcements then
offer "Also email the N registered drivers" (everyone, or only chosen run groups such
as Instructor, with or without showing it in the app), sent by the `push-schedule`
function (`email` action) through the same Gmail account as the coaching
emails (`SMTP_USER` / `SMTP_PASS`), 50 per message in Bcc. The list
(`event_roster`) is visible only to the event's organizers and is deleted a
week after the event by a `pg_cron` job. ClubReg's Report Builder export (an
`.xls` that is an HTML table) uploads as is; cancelled entries are skipped. If
it includes Run Group and Advanced Coaching Quantity, Admin → Coaching lists
who paid for coaching and how many of their sessions are booked, with a Book
button that fills in the form.

**ClubReg sync.** Under Registered drivers, organizers can link the event to its ClubReg
event number (each ClubReg event can be linked to only one event). The `ClubReg sync` GitHub Action (`.github/workflows/clubreg-sync.yml`,
`scripts/clubreg-sync.ts`) then runs at 5:15 AM Eastern, and from two days before the event
through its last day logs in to ClubReg, exports Report Builder's list for each linked event
and sends it to `push-schedule` (`roster-due` / `roster-pull` actions). That replaces the
list and logs who was added and who cancelled (`roster_pulls`, shown in Admin). A failed or
empty pull keeps the current list. Setup: repository secrets `CLUBREG_EMAIL`,
`CLUBREG_PASSWORD` and `ROSTER_SYNC_TOKEN`, plus the same `ROSTER_SYNC_TOKEN` as an Edge
Function secret in Supabase. Run it by hand from Actions → ClubReg sync → Run workflow.

### Phone alerts

Drivers using the web version can tap Turn on alerts (top of Now, Schedule and My Day
while alerts are off; alerts end the day after their event) to
get a phone notification when their event's schedule is changed in Admin. On
iPhone this needs the home screen app (iOS 16.4+). It is sent by the Edge
Function in `supabase/functions/push-schedule`. One-time setup:

1. Run `supabase/setup.sql` again. It adds the alert tables.
2. Edge Functions → Deploy a new function → Via Editor. Name it
   `push-schedule`, replace the sample code with
   `supabase/functions/push-schedule/index.ts`, and click Deploy. Then open
   its Details and turn **Verify JWT** off (the function checks the organizer's
   sign-in itself).
3. Sign in to Admin once. That makes the alert keys; until then the alerts
   card stays hidden. No secrets to add.

Drivers who are signed in on My Day when alerts are on also get alerts about
their own coaching sessions and check rides (booked, changed, cancelled, or
moved by a schedule change), and a reminder 15 minutes before each one. The
same goes for instructors with an email on the booking. The reminders come from
a `pg_cron` job, made by `setup.sql`, that calls the function every minute.
Times are worked out in the track's time zone (`events.time_zone`, guessed from
the state in the event's location).

### Driver list

An optional "Stay in the loop" card at the bottom of the Now tab lets drivers
leave their name and email, agreeing that the event's club may email them.
Each club's organizers see their own list at the bottom of the Admin tab, can
remove people, and can download it as a spreadsheet (.csv). Setup: run
`supabase/setup.sql` again (it adds the `driver_signups` table).

### Feedback

Drivers rate an event or the app from 1 to 5 stars, with an optional comment,
from the My Day tab (no sign-in needed). Club admins see the average and comments
for their events at the bottom of the Admin tab; platform admins also see
feedback about the app.

## Website version

Every push to `main` publishes the web version to GitHub Pages
(`.github/workflows/deploy-web.yml`).

## Running it

```bash
npm install
npx expo start        # then scan the QR code with the Expo Go app on your phone
npm run typecheck
node scripts/build-preview.mjs dist/preview.html   # one-file web preview
```
